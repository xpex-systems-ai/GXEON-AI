# GXEON Roadmap

## Roadmap principle

GXEON OS should activate in phases. Each phase must preserve auditability, explicit approvals, and honest status reporting.

## Phase P0 — Investor Visual Demo

**Status:** current package

- Investor-facing README and docs.
- Vercel visual preview readiness.
- Safe preview dashboard copy.
- APIs disabled and integrations pending.
- No production claims.

## Phase P1 — Supabase Readiness

**Status:** pending secure environment

- Inject Supabase/Postgres variables securely.
- Run non-mutating validation.
- Confirm Drizzle financial schema readiness.
- Keep database push/migrations gated by explicit approval.

## Phase P2 — Revenue Engine MVP

**Status:** planned

- Opportunity model.
- Proposal model.
- Client/project pipeline.
- Manual-first financial tracking.
- AI-assisted proposal drafting with human approval.

## Phase P3 — Controlled Integrations

**Status:** planned

- API Gateway activation policy.
- Supabase browser/client boundaries.
- Payment provider readiness with no secret exposure.
- GitHub/Vercel preview flow for release review.

## Phase P4 — Automation and Reporting

**Status:** planned

- Human-approved playbooks.
- Operator reports through Microsoft 365 / Copilot workflows.
- Analytics and status reporting.
- No autonomous production actions without approval.

## Phase P5 — Advanced Marketplace and Blockchain

**Status:** future roadmap

- Marketplace expansion.
- Reputation/portfolio evidence surfaces.
- Blockchain and on-chain modules only after core revenue flows are validated.
- Deep provider integrations after security review.

## Current risks

- Supabase activation requires credentials and explicit database approval.
- Vercel preview setup depends on correct project linkage in Vercel.
- Dashboard currently demonstrates flows visually; production runtime work remains planned.
