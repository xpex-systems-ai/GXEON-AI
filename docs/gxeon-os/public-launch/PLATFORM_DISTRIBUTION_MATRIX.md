# Platform Distribution Matrix

| Channel | Format | Objective | Copy angle | CTA | Frequency | Risk | Anti-spam rule |
| --- | --- | --- | --- | --- | --- | --- | --- |
| GitHub | README + docs | Technical trust | Operating system for evidence-led execution | Review repo / open issue | Update when real changes ship | Overclaiming | Keep status labels visible |
| LinkedIn | Launch post + weekly updates | Partners, clients, investors | From conversation to system | Comment or book focused call | 2-4 posts/week | Hype | No fake metrics or mass tagging |
| X/Twitter | Threads | Dev reach | Architecture, safety, build-in-public | Read repo / reply with feedback | 2 threads/week | Shallow engagement | No engagement bait |
| YouTube | 5-8 min videos | Explain product | Repo walkthrough and Audit OS demo | Subscribe / review docs | 1/week | Exposing secrets | Record clean demo env only |
| TikTok/Reels/Shorts | 30-60s clips | Awareness | Strong hooks, visible diagrams | Visit README | 2-3/week | Overpromising | No income guarantees |
| Instagram | Carousel | Visual narrative | What GXEON is / is not | Save and share | 1-2/week | Fake authority | No third-party logos |
| Medium | Narrative essay | Investor/partner context | Conversation to code to operating system | Read one-pager | 1 launch article | Unsupported claims | Use honest status labels |
| Dev.to/Hashnode | Technical article | Dev credibility | Safety-first architecture | Review docs | 1 launch article | Too promotional | Include implementation details |
| Reddit | Community post | Feedback | Build-in-public request | Ask for critique | Selectively | Spam perception | Follow each community rule |
| WhatsApp/Telegram | Private note | Warm intros | Short human context | Reply if relevant | Limited | Spam | Send only to relevant contacts |
