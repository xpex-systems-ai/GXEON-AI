## 4. Draft policy patterns

```sql
-- Design only. Do not execute in Mission 04A.
create policy avatars_read_public on storage.objects
  for select to anon, authenticated
  using (bucket_id = 'avatars');

create policy avatars_write_own on storage.objects
  for insert to authenticated
  with check (
    bucket_id = 'avatars'
    and (storage.foldername(name))[1] = 'actors'
    and (storage.foldername(name))[2] = public.current_actor_id()::text
  );
```

```sql
-- Design only. Do not execute in Mission 04A.
create policy dataset_assets_select_authorized on storage.objects
  for select to authenticated
  using (
    bucket_id = 'dataset-assets'
    and exists (
      select 1
      from public.marketplace_datasets d
      left join public.dataset_purchases p
        on p.dataset_id = d.id
       and p.buyer_actor_id = public.current_actor_id()
       and p.status in ('paid', 'active')
      where d.id::text = (storage.foldername(storage.objects.name))[2]
        and (d.owner_actor_id = public.current_actor_id() or p.id is not null)
    )
  );
```

## 5. Operational rules

1. No public bucket for paid datasets.
2. No service role key in web/mobile upload code.
3. Prefer signed upload URLs generated by backend for sensitive buckets.
4. Object metadata must not contain secrets, provider payloads or raw payment details.
5. Receipt generation and proof artifact writes should be server-mediated.
6. Storage deletion should be soft-delete/audit-aware where business records reference objects.
